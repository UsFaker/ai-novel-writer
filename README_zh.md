# ✍️ AI 小说创作工作流 Skill

[English Version](README.md) | [中文版](README_zh.md)

> 给 AI 一套作家的工作方式，而不是一摞审批表。
> **控制在结构，自由在句子**：档案锁死事实、因果和秘密的进度，正文的每个句子从人物的当下重新生长。

## 🎯 解决什么问题

| 痛点 | 病根 | 本工作流的解法 |
|------|------|----------------|
| 长篇情绪节奏失控，高潮不高、连读很机械 | 用"情绪强度数字"排节奏，音量涨了赌注没涨 | **张力波形 + 加码原则 + 呼吸章 + 情绪债**：情绪跟着处境走，欠读者的憋屈必须按窗口偿还 |
| 章与章衔接断裂，每章像独立短篇 | 大纲按"每章一格"生成，格子之间没有因果 | **因果链节拍卡 + 接力卡 + 链读检查**：每章必须接住上一章"留给下一章"的东西 |
| 整体剧情没书感，换地图打怪 | 只有事件清单，没有命题和代价 | **故事核（终极问题 + 错误信念）+ 卷表（永远失去什么）+ 底牌表**：命运一卷卷收紧 |
| 越管越乱、越改越臃肿 | 每个症状加一层流程，规则互相重复打架 | **五件套封顶**：全项目只有五类档案，一处事实只记一次；测试脚本给每个文件设了行数预算 |

## 📦 五件套（每个小说项目的全部档案）

```
故事核.md        这本书为什么值得写完：终极问题、错误信念、对立面、底牌表
characters/      每角色一档：触发机制、对话风格、信息边界
outlines/
├── 全书结构.md  卷表（命运递进）+ 弧卡（8-25章的因果闭环）
├── 节拍_弧X.md  逐章节拍卡：承接 → 选择 → 意外 → 后果 → 留给下一章
└── 账本.md      硬事实（只增不改）/ 角色现状 / 线头与情绪债 / 接力卡
```

写一章的闭环：**备料 → 开笔三问 → 作家稿 → 修稿（硬伤→链条→人味）→ 记账 → 简报**。
弧末做链读检查并生成下一弧节拍；卷末做卷末三问并修订后续卷表。

## 🧭 创作观（整套工作流的四条底层原则）

1. **剧情是因果，不是清单** —— 相邻两章必须能用"因此/但是"连接，只能用"然后"的地方就是断链
2. **情绪是读者对赌注的心跳** —— 要紧张就加码缩时砍退路，要松弛就兑现小胜利；禁止用情绪词装情绪
3. **秘密是欠读者的债** —— 底牌只有三种状态：埋着 → 半开 → 亮出，每翻一层必须付代价、留新问题
4. **控制在结构，自由在句子** —— 规划语言永不进正文

## 🚀 快速开始

1. 从 [`skills/ai-novel-writer/SKILL.md`](skills/ai-novel-writer/SKILL.md) 开始，了解路由与单章闭环。
2. 新项目按顺序执行 `prompts/01 → 02 → 03 → 04`，建好账本后即可让 AI "写下一章"。
3. 长篇（100万字+）不需要更多文件种类，只需要更多卷和弧卡——容量预算见 `03_book_structure.md`。
4. 旧版项目（故事宪法/资产库/批次上下文包等）：SKILL.md 的"旧项目迁移"一节会把它们合并进五件套。

## 💡 关键提示

- **每次只生成一个弧的节拍**（8-25 章），写到弧末再生成下一弧——远粗近细。
- **账本是唯一需要每章更新的档案**，接力卡取代了所有"下一章方向文档"。
- **AI 只在两种情况下停下来**：缺料（该有的档案不存在）和撞账（与既成事实冲突）。其余偏差写进简报，不停工。
- **改这套 skill 时先跑测试**：`powershell -File tests/skill_quality_checks.ps1`。行数预算超了，先删再加。
