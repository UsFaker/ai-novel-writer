# 阶段 7：动态角色状态追踪

## 使用说明

**每完成一章的终稿后，必须立即执行本阶段。** 这是保证后续章节角色行为一致性的核心机制。

本阶段的产出是一份**动态角色状态表**，记录截至当前章节结束时，所有登场角色的最新状态。这份表格会作为后续章节生成（阶段 5）和一致性审查（阶段 6）的**强制输入项**。

核心理念：**角色档案是静态的"出厂设置"，角色状态表是动态的"实时快照"。两者缺一不可。**

---

## 提示词模板

```
你是一位极其严谨的小说连载编辑，专职负责维护角色的实时状态记录，确保连载过程中不出现角色遗忘或前后矛盾的问题。

## 角色原始档案
【粘贴所有已创建的角色性格档案（阶段 2 产出）】

## 上一版角色状态表
【如果是第一章之后，则粘贴初始状态；如果是后续章节，则粘贴上一章更新后的状态表】

## 本章终稿正文
【粘贴刚刚完成的章节终稿全文】

## 任务

请根据本章发生的事件，更新角色状态表。对于本章中**没有登场**的角色，状态保持不变，直接沿用上一版数据。

## 状态表格式

为每一个已登场的角色（含仅被提及的角色）维护以下字段：

### 角色状态卡片

| 字段 | 说明 |
|------|------|
| **角色名** | 角色全名 |
| **存活状态** | 存活 / 重伤 / 死亡 / 失踪 / 未知 |
| **当前位置** | 截至本章结束时，角色在哪里 |
| **身份/头衔变化** | 有无新的身份、称号或地位变动（如从杂役变为记名弟子） |
| **已知信息** | 该角色目前知道哪些关键信息（列出关键词即可） |
| **不知道的关键信息** | 该角色目前不知道但读者已知的重要信息（信息差是制造张力的核心） |
| **当前情绪状态** | 截至本章结束时的主要情绪 |
| **与主角关系** | 一句话描述当前与主角的关系（含变化方向：↑亲近 / ↓疏远 / →不变 / ⚡冲突） |
| **身体状态** | 有无受伤、中毒、异变等物理影响 |
| **持有物品/能力** | 当前持有的重要物品或已获得/失去的能力 |
| **本章关键行为** | 本章中该角色做了什么重要的事（最多 3 条） |
| **待回收的伏笔** | 与该角色相关的、尚未解开的悬念或伏笔 |

### 特别标注区

在状态表底部，额外标注以下高危信息：

- 🔴 **本章死亡角色**：哪些角色在本章确认死亡（后续章节绝对不能再让他们活着出场）
- 🟡 **本章新增角色**：哪些角色是本章首次登场的（需要记录初始印象和设定）
- 🟢 **关系重大变化**：哪些角色之间的关系发生了质变（如从盟友变为敌人）
- ⚠️ **信息差更新**：哪些角色知道了新的关键信息，哪些角色仍被蒙在鼓里

## 输出格式

1. 按角色分块输出状态卡片
2. 在所有卡片之后输出"特别标注区"
3. 最后附一行"状态表更新截止章节：第 X 章"
```

---

## 注意事项

1. **每写完一章就必须更新**——千万不要攒几章再补，信息会丢失
2. **死亡角色必须标红**——这是最容易出现"意外复活"BUG 的地方
3. **信息差是核心价值**——记清楚"谁知道什么、谁不知道什么"，这直接决定对话和行为的合理性
4. **状态表要和角色档案配合使用**——档案告诉你角色"会怎么做"，状态表告诉你角色"现在能做什么"
5. **新角色必须建卡**——哪怕只是一个路人甲，只要有名字就建一张最简卡片
6. **状态表是累积文档**——越往后越厚，但不要删除已死亡角色的卡片，保留并标注死亡章节
