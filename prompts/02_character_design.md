# 阶段 2：角色性格档案生成

## 使用说明

为每一个重要角色单独执行一次本提示词。在 `【】` 标记处填入具体内容。
建议优先创建主角，再创建对手/反派，最后创建核心配角。
**务必将阶段 1 的故事概念文档一并提供给 AI 作为上下文。**

---

## 提示词模板

```
你是一位资深小说角色设计专家，擅长创造立体、真实、有内在逻辑的小说角色。

## 上下文
【在这里粘贴阶段1生成的故事概念文档（或其摘要）】

## 角色基础信息
- 角色名称：【名字】
- 年龄：【年龄】
- 性别：【性别】
- 职业/身份：【职业或社会身份】
- 故事定位：【主角 / 反派 / 配角，以及在故事中的核心作用】
- 特殊要求：【如果有，如"必须是左撇子"、"有口吃"等】

## 生成要求

请严格按照以下结构生成角色性格档案。注意：**不要使用抽象标签**，每一项都必须落实到具体的行为和场景。

### 1. 核心性格特征（3-5 个）

为每个特征提供：
- **特征名称**：一个精准的词
- **正面表现**：这个特征在顺境中如何体现（举一个具体场景）
- **负面表现**：这个特征在压力下如何扭曲（举一个具体场景）
- **形成原因**：什么经历造就了这个特征

要求：必须包含至少 1 个明显缺陷，避免完美人设。

### 2. 情绪触发机制

这是角色行为一致性的核心，请详细设计：

- **崩溃触发点**：描述一个具体场景——当发生 ______ 时，角色会失控，表现为 ______（要具体到动作和语言）
- **原则违背点**：角色有一条绝不会打破的底线是 ______，但如果 ______ 发生，他/她会被迫违背，违背后会 ______
- **情绪爆发点**：最能激怒角色的事情是 ______，爆发时的外在表现是 ______
- **防御机制**：角色面对不愿面对的事情时，本能的回避方式是 ______（如冷笑话岔开话题/沉默不语/反过来攻击对方/理性化解释一切）
- **柔软时刻**：什么情况会让角色卸下防备，展露脆弱（这是最能打动读者的瞬间）

### 3. 童年影响事件（1-2 个关键经历）

对每个事件，提供：
- **事件描述**：发生了什么（用 3-5 句话讲清楚，要有画面感）
- **当时的情绪**：童年的角色在那一刻感受到了什么
- **心理烙印**：这件事在角色心里种下了什么信念（如"不能相信任何人"/"只有强大才能保护想保护的人"）
- **行为模式**：这个信念在成年后如何具体体现在日常行为中

### 4. 对话风格特征

- **说话节奏**：语速快/慢？喜欢长句还是短句？有什么停顿习惯？
- **口头禅/高频用词**：列出 2-3 个角色常用的表达方式
- **情绪表达方式**：
  - 高兴时怎么表达（是直接笑还是嘴硬？）
  - 生气时怎么表达（是冷暴力还是爆发？）
  - 伤心时怎么表达（是沉默还是伪装？）
- **潜台词模式**：这个角色最常见的"话里有话"方式是什么（举一个例子：表面说______，实际意思是______）

### 5. 行为惯性

- **冲突反应**：面对冲突的第一反应是什么（战斗/逃跑/冻结/讨好），然后呢？
- **决策模式**：做重要决定时是理性分析型/跟着感觉走/犹豫不决还是冲动行事？
- **人际距离**：和人交往的默认距离是什么（热情主动/礼貌疏离/刺猬型），对什么样的人会打破这个默认距离？
- **压力应对**：长期承受压力时，角色会出现什么变化（失眠？暴食？疯狂工作？变得冷漠？）
- **小习惯**：列出 2-3 个与性格相关的身体动作习惯（如紧张时摸耳朵、思考时咬嘴唇）

### 6. 性格矛盾点

设计角色的内在撕裂感（这是让角色立体的关键）：

- **表面 vs 内心**：别人眼中的角色是 ______ 的，但角色真实的内心是 ______
- **渴望 vs 恐惧**：角色最渴望得到 ______，但最害怕的恰恰是 ______
- **价值观 vs 行为**：角色坚信 ______，但在故事中却不得不做出 ______ 的行为，因为 ______

### 7. 角色关系预设

- **与主角的关系**（如果不是主角）：初始关系 → 重要转折点 → 最终关系
- **最信任的人**：是谁？为什么信任？一旦这个人背叛会怎样？
- **最在意的人**：是谁？愿意为这个人做到什么程度？
- **天然的敌人类型**：什么类型的人会和角色天然产生冲突？

### 8. 成长弧线方向

- **故事开始时的状态**：角色在情感/能力/认知上的起点
- **需要克服的核心障碍**：角色成长路上最大的内心障碍是什么
- **成长的代价**：角色成长意味着要放弃什么或接受什么
- **故事结束时的状态**：角色的终点（不需要详细，一句话即可）

## 输出格式

请用结构化的方式输出，每个部分使用清晰的标题和分点。
对于需要举例的地方，请给出具体的场景片段而非抽象描述。
```

## 角色档案文件管理规范（重要）

### 文件存储方式

**每个角色必须保存为单独的 `.md` 文件**，禁止将所有角色放在同一个文件中。

#### 文件命名规范
```
characters/
├── README.md              # 角色档案索引，列出所有角色
├── 陆沉.md                # 主角
├── 缝针人.md              # 重要配角
├── 沈寂.md                # 反派/宿敌
├── 阿芜.md                # 次要角色
└── ...
```

#### 单角色文件模板

每个角色文件必须按照 prompt 产出的 8 部分结构存储：

```markdown
# 角色名（定位，如：主角/反派/配角）

## 基础信息
- **姓名**：
- **年龄**：
- **性别**：
- **身份**：
- **当前状态**：存活/已死/失踪
- **外貌特征**：（简要描述，不要超过3句）
- **特殊要求**：（如有）

## 1. 核心性格特征
（3-5 个特征，每个含正面表现、负面表现、形成原因。至少 1 个明显缺陷）

## 2. 情绪触发机制
（崩溃触发点、原则违背点、情绪爆发点、防御机制、柔软时刻）

## 3. 童年影响事件
（1-2 个关键经历，含事件描述、当时情绪、心理烙印、行为模式）

## 4. 对话风格特征
（说话节奏、口头禅/高频用词、情绪表达方式、潜台词模式）

## 5. 行为惯性
（冲突反应、决策模式、人际距离、压力应对、小习惯）

## 6. 性格矛盾点
（表面 vs 内心、渴望 vs 恐惧、价值观 vs 行为）

## 7. 角色关系预设
（与主角关系、最信任的人、最在意的人、天然敌人类型）

## 8. 成长弧线方向
（故事开始时状态、核心障碍、成长代价、故事结束时状态）
```

#### README.md 索引格式

```markdown
# 角色档案目录

## 主要角色

| 角色 | 文件 | 状态 | 备注 |
|------|------|------|------|
| [陆沉](./陆沉.md) | 陆沉.md | 存活 | 主角，"钥匙" |
| [缝针人](./缝针人.md) | 缝针人.md | 存活 | 陆沉的新师父 |

## 敌对角色

| 角色 | 文件 | 状态 | 备注 |
|------|------|------|------|
| [沈寂](./沈寂.md) | 沈寂.md | 活跃 | 清渊司精英，宿敌 |

## 新增角色规范

创建新角色时：
1. 在 `characters/` 目录新建 `{角色名}.md`
2. 更新 `README.md` 索引
3. 更新 [角色状态表](../notes/角色状态表.md)
```

### 为什么必须拆分？

1. **方便查找**：写某角色时直接打开对应文件，不需要在长篇文档中翻找
2. **避免冲突**：多人协作或AI处理时，单文件修改不会互相覆盖
3. **动态扩展**：随时新增角色，不影响已有档案
4. **版本控制**：Git能精确追踪每个角色的修改历史

---

## 注意事项

1. **每次只生成一个角色**——不要贪多，一个一个打磨
2. **先做主角**——主角的档案是其他角色的参照基准
3. **反派也需要档案**——好的反派需要和主角一样立体的内心逻辑
4. **角色档案生成后要保存好**——后续所有阶段都会引用
5. **如果角色感觉"平"**——检查触发机制和性格矛盾点是否足够尖锐
6. **务必拆分到单独文件**——不要在同一个md文件里堆叠多个角色

## 渐进式角色引入（长篇小说专用）

**长篇小说（100万字以上）不要在开始时一次性设计所有角色。** 按全书蓝图（阶段 0）中的角色引入计划，分弧分批创建角色档案。

### 引入原则

1. **按弧引入**：每个弧只设计该弧需要引入的新角色，不要提前设计后续弧的角色
2. **角色预算**：每个弧新增核心角色不超过 3-5 个，否则读者记不住
3. **设计时机**：在弧开始前（弧结束检查点的第 4 步）执行本阶段，为新弧批量创建角色
4. **退场规划**：每个角色在创建时就要想清楚他的退场方式和大约时机

### 角色档案扩展字段

在长篇模式下，每个角色档案的「基础信息」部分增加以下字段：

```markdown
## 基础信息
- ...（原有字段）
- **引入弧**：第 X 弧（弧名称）
- **预计退场**：第 Y 弧（退场方式：死亡/离队/背叛/沉寂/贯穿全书）
- **角色生命周期**：短期（1弧）/ 中期（2-3弧）/ 长期（贯穿全书）
```

### 角色批次管理

每开始一个新弧时，对照全书蓝图的角色引入计划：

1. 确认本弧需要新增哪些角色
2. 逐个执行本阶段的 prompt，生成完整档案
3. 更新 `characters/README.md` 索引，标注角色所属弧
4. 在阶段 7 角色状态表中为新角色建卡
