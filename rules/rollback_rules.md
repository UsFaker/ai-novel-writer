# 章节回退与快照规则

> 本规则定义两个操作：**每章完成后自动创建快照** 和 **回退到指定章节**。

---

## 一、快照创建规则

### 触发时机

每章 STEP 7（报告完成）之前自动执行。

### 快照内容

仅快照以下两个**原地更新**的文件：

| 文件 | 来源 | 说明 |
|------|------|------|
| 角色状态表 | `outlines/` 中文件名含"角色状态"的文件 | 每章原地覆盖更新，无法从现有文件恢复旧版本 |
| 累积事实清单 | `outlines/` 中文件名含"事实"的文件 | 虽然"只增不改"，但回退时需要删除后续章节追加的条目 |

> **为什么不快照其他文件？**
> - `chapters/`、`drafts/`、`scenes/` 中的文件按章编号独立存储，回退时直接删除即可
> - `concept.md`、`characters/`、`outlines/情绪节拍*.md` 在写章节时不会被修改

### 存储位置与命名

```
snapshots/
├── after_ch001/
│   ├── 角色状态表.md        # 第1章完成后的角色状态表完整副本
│   └── 累积事实清单.md      # 第1章完成后的事实清单完整副本
├── after_ch002/
│   ├── 角色状态表.md
│   └── 累积事实清单.md
└── ...
```

- 目录名格式：`after_ch{章节号，3位数字补零}`
- 文件名与源文件保持一致
- 每个快照目录包含完整的文件副本（不是增量）

### 创建流程

1. 确定刚完成的章节号 N
2. 创建目录 `snapshots/after_ch{N:03d}/`
3. 将当前角色状态表的**完整内容**复制到快照目录
4. 将当前事实清单的**完整内容**复制到快照目录
5. 如果该快照目录已存在（如重写章节），覆盖旧快照

### 保留策略

- 保留所有快照，不自动清理
- 快照仅包含文本文件，存储开销极小

## 二、回退执行流程（6 步）

### STEP R1: 确认目标

1. 从用户指令中提取目标章节号 M
2. 含义确认："回退到第M章" = **保留第1章到第M章**，删除第M+1章及之后的所有内容
3. 扫描 `snapshots/` 目录，确认 `after_ch{M:03d}/` 快照是否存在

→ ❌ 快照不存在？执行 **STEP R1-fallback**（见下方）

### STEP R2: 清点影响范围

扫描以下目录，列出所有将被删除的文件：

| 目录 | 删除范围 | 说明 |
|------|---------|------|
| `chapters/` | 第 M+1 章及之后的终稿 | 按文件名中的章节号判断 |
| `drafts/` | 第 M+1 章及之后的初稿和方向文档 | 包括 `方向_第X章.md` |
| `scenes/` | 第 M+1 章及之后的场景素材 | 按文件名中的章节号判断 |
| `snapshots/` | `after_ch{M+1}` 及之后的快照 | 清除已废弃的快照 |

以清单形式向用户展示：

```
⚠️ 即将回退到第 M 章，以下内容将被删除：

📁 chapters/
  - 第X章_xxx.md
  - 第Y章_xxx.md
  ...

📁 drafts/
  - 第X章_xxx.md
  - 方向_第X章.md
  ...

📁 scenes/
  - 场景_第X章_xxx.md
  ...

📁 snapshots/
  - after_ch{M+1}/
  ...

📄 角色状态表将恢复到第 M 章完成后的版本
📄 事实清单将恢复到第 M 章完成后的版本

确认执行回退？（是/否）
```

### STEP R3: 等待用户确认

- 用户确认"是"后才执行
- 用户说"否"或"取消"则终止回退

### STEP R4: 恢复快照文件

1. 读取 `snapshots/after_ch{M}/角色状态表.md` 的完整内容
2. 覆盖写入 `outlines/` 中的角色状态表文件
3. 读取 `snapshots/after_ch{M}/累积事实清单.md` 的完整内容
4. 覆盖写入 `outlines/` 中的事实清单文件

### STEP R5: 删除废弃文件

按 STEP R2 列出的清单，删除所有目标章节之后的产出文件：

1. 删除 `chapters/` 中第 M+1 章及之后的文件
2. 删除 `drafts/` 中第 M+1 章及之后的文件（含方向文档）
3. 删除 `scenes/` 中第 M+1 章及之后的文件
4. 删除 `snapshots/` 中 `after_ch{M+1}` 及之后的目录

### STEP R6: 报告回退结果

向用户简报：

```
✅ 已成功回退到第 M 章

- 恢复了角色状态表（截止第 M 章）
- 恢复了事实清单（截止第 M 章）
- 删除了 X 个章节文件
- 删除了 X 个草稿/方向文件
- 删除了 X 个场景文件
- 删除了 X 个废弃快照

📌 当前最新章节：第 M 章
💡 可以直接说"写下一章"从第 M+1 章重新开始
```

## 三、无快照时的降级处理（STEP R1-fallback）

当目标章节没有快照时（功能添加前写的章节），执行以下流程：

### 情况 A：有更早的快照可用

如果存在 `after_ch{K}/`（K < M），可以：
1. 从 K 的快照恢复状态表和事实清单
2. 然后读取第 K+1 到第 M 章的终稿，重新提取事实并更新状态表
3. 这是一个**耗时操作**，需要提醒用户

### 情况 B：完全没有快照

通知用户：

```
⚠️ 未找到第 M 章的快照，也没有更早的快照。
这可能是因为该章节在启用快照功能之前完成的。

建议操作：
1. 手动回退：删除第 M+1 章之后的 chapters/、drafts/、scenes/ 文件
2. 手动修复状态表：参照第 M 章终稿内容，手动更新角色状态表
3. 手动修复事实清单：删除事实清单中编号 [F{M+1}-xx] 及之后的条目

💡 建议：回退完成后执行一次"创建快照"为当前状态建立快照基线。
```

## 四、手动创建快照

用户可以随时说"创建快照"或"保存快照"来为当前状态创建快照：

1. 扫描 `chapters/` 找到最新章节号 N
2. 创建 `snapshots/after_ch{N:03d}/`
3. 复制当前角色状态表和事实清单

这在以下场景有用：
- 为旧章节补建快照
- 手动修改状态表后创建新的快照基线

---

## 铁律

- **回退前必须向用户展示完整影响清单并获得确认** — 禁止静默删除文件
- **快照必须是完整副本** — 禁止增量快照，确保任意快照可独立恢复
- **覆盖前先恢复** — STEP R4（恢复快照）必须在 STEP R5（删除文件）之前执行
- **回退不可逆** — 提醒用户回退操作会永久删除后续章节的文件
- **快照目录命名必须补零到3位** — 确保文件系统排序正确（如 `after_ch001` 而非 `after_ch1`）
