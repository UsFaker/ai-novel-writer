# 状态与事实追踪规则

## 角色状态卡片格式（每章更新）

为每一个本章登场角色维护以下字段：

| 字段 | 说明 |
|------|------|
| **角色名** | 角色全名 |
| **存活状态** | 存活 / 重伤 / 死亡 / 失踪 / 未知 |
| **当前位置** | 截至本章结束时所在位置 |
| **身份/头衔变化** | 有无新的身份、称号或地位变动 |
| **已知信息** | 该角色目前知道的关键信息（关键词） |
| **不知道的关键信息** | 该角色不知道但读者已知的信息（信息差 = 张力） |
| **当前情绪状态** | 截至本章结束时的主要情绪 |
| **与主角关系** | 一句话描述（含变化方向：↑亲近/↓疏远/→不变/⚡冲突） |
| **身体状态** | 有无受伤、中毒、异变等 |
| **持有物品/能力** | 当前持有的重要物品或已获得/失去的能力 |
| **本章关键行为** | 本章中的重要行为（最多3条） |
| **待回收的伏笔** | 与该角色相关的未解悬念 |
| **最后出场章节** | 最近一次实际出场的章节号，用于遗忘元素提醒 |
| **活跃状态** | 活跃 / 暂停 / 完结 / 退场，避免已退场角色反复误报 |

未登场角色直接沿用上一版数据。

### 特别标注区（状态表底部）
- 🔴 **本章死亡角色**（后续绝对不能再活着出场）
- 🟡 **本章新增角色**
- 🟢 **关系重大变化**
- ⚠️ **信息差更新**

末行注明：状态表更新截止章节：第 X 章

## 事实清单格式（每章追加，只增不改）

### 分类与编号规则

每条事实编号格式：`[FX-YY]`（X=章节号，YY=序号）

```
## 第 X 章事实清单

### 🔴 生死事实（最高优先级）
- [FX-01] 谁死亡/重伤？死因？目击者？

### 🟠 物品/能力变动
- [FX-02] 谁获得/失去了什么？

### 🟡 身份/关系变动
- [FX-03] 谁的身份/关系发生不可逆变化？

### 🔵 信息/秘密揭示
- [FX-04] 揭示了什么？谁知道？谁不知道？

### 🟢 伏笔管理
- [新] 本章埋下的新悬念
- [回收] 回收了哪个伏笔（来源：第X章）
- [待回收] 按节奏应回收但未回收的伏笔

### ⚪ 时间线
- 本章时间跨度：
- 累积时间线：
```

### 铁律
- 事实清单**只增不改**——已记录事实不能删除或修改
- 已死亡 = 后续章节绝对不能活着出场
- 每个事实必须编号——方便引用
- 事实清单 + 角色状态表 = 后续章节的硬约束

## 长期追踪索引（可选但推荐）

长篇项目建议在 `outlines/` 中维护弧线/伏笔/时间线/关系追踪文件。若文件存在，每章 STEP 6 必须同步更新。

### 全书关键资产库

百万字级项目必须维护 `outlines/全书关键资产库.md`，用于管理关键物品、核心秘密、力量规则、反派计划、世界真相、主角身世、组织制度、地点机关、关系真相和终局钥匙。

每章完成后，如涉及关键资产，必须更新：

| 字段 | 说明 |
|------|------|
| **资产ID/名称** | 对应资产库中的唯一条目 |
| **当前持有者/控制者** | 谁拿着、谁能使用、谁只能看见 |
| **当前解锁层级** | 影子 / 接触 / 误用 / 局部揭示 / 真相 / 高潮 |
| **本章使用方式** | 异常、误判、代价、局部揭示、交易、损坏、转移等 |
| **读者已知** | 本章后读者知道了什么 |
| **主角已知** | 本章后主角知道了什么 |
| **反派/对立面已知** | 本章后对立面知道了什么 |
| **仍禁止暴露** | 后续仍不能提前说破的用途、来源、规则、真相 |
| **下次允许推进窗口** | 预计在哪一章/小弧/卷继续推进 |

规则：
- 关键资产不能因为“材料里有”就进入正文；必须检查资产库权限。
- 前十章只允许影子、异常、误判和短线危机，不得完整解释关键物品、力量规则、主角身世、反派计划和终局钥匙。
- 资产解锁必须带来代价、风险、关系变化、局势变化或新问题。
- 若正文已经让资产发挥超过当前解锁层级的功能，必须标记为硬伤并重写或调整资产库。

### 长篇结构索引

百万字级项目必须维护 `outlines/长篇结构索引.md`，至少包含：

| 字段 | 说明 |
|------|------|
| **当前宏观阶段/篇** | 全书方向层，不等于卷或小弧 |
| **当前卷** | 40-100 章左右的阶段任务 |
| **当前剧情单元/小弧** | 8-30 章内的冲突闭环 |
| **当前章段批次** | 10-20 章左右的连续情绪节拍生成单位 |
| **已完成到第几章** | 写作进度指针 |
| **下一章节拍来源** | 指向具体情绪节拍文件和批次 |

规则：每章完成后，如跨过批次/小弧/卷边界，必须更新当前进度指针。缺少下一章节拍时，只补当前结构索引指向的批次，不得用全书大弧直接替代章纲。

### 故事线事件追踪表

长篇项目不能只记录“活跃/潜伏”，必须按事件追踪故事线：

| 字段 | 说明 |
|------|------|
| **故事线名称** | 如灭灵线、感情线、身世线、势力线 |
| **事件类型** | 伏笔 / 推进 / 转折 / 高潮 / 收束 |
| **发生章节** | 第几章发生 |
| **事件内容** | 具体发生了什么 |
| **造成的变化** | 信息、关系、局势、资源、威胁、决定、代价中哪一项改变 |
| **关联角色/势力** | 涉及谁 |
| **后续承诺** | 读者会等待什么后续 |
| **预计反馈/回收窗口** | 预计在哪几章或哪个小弧反馈 |

规则：
- 活跃故事线 10+ 章没有任何事件时，必须提醒用户选择：本章推进 / 标记暂停 / 标记完结。
- 同一故事线连续 3 次只有“推进”而没有“转折/高潮/收束”，必须提醒节奏单调。
- 新伏笔必须有反馈或回收窗口；没有窗口的伏笔不能进入正式事实清单。
- 每章至少应让一个活跃故事线发生事件级变化；如果本章没有任何故事线事件，需在审查中标记为弱章。

### 活跃情节线

| 字段 | 说明 |
|------|------|
| **情节线名称** | 如复仇线、感情线、寻物线 |
| **当前状态** | 活跃 / 暂停 / 完结 |
| **上次推进章节** | 最近一次实际产生进展的章节 |
| **下一次建议推进** | 建议在哪几章内再触碰 |
| **当前悬念** | 读者还在等什么答案 |

规则：活跃情节线 12+ 章无推进时，必须提醒用户选择：本章推进 / 标记暂停 / 标记完结。

### 伏笔索引

| 字段 | 说明 |
|------|------|
| **伏笔ID** | 例如 `P03-01` |
| **埋设章节** | 第几章埋下 |
| **内容** | 伏笔是什么 |
| **关联角色/物品/地点** | 便于后续检索 |
| **计划回收窗口** | 预计第几章或哪个弧回收 |
| **状态** | 新增 / 待回收 / 已回收 / 延后 / 废弃 |

规则：伏笔 20+ 章未回收且未标注延后原因时，必须在简报中提醒；已回收伏笔必须写明回收章节和回收方式。

### 时间线与关系索引
- 记录每章时间跨度、地点移动和关键同时事件，避免旅行时间、昼夜、伤病恢复矛盾。
- 记录核心关系的变化方向和触发事件，不允许关系突然跳级而没有场景依据。
